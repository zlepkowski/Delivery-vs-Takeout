# Test rules: Pickup or Delivery

## Layout

```
tests/
  helpers/load.js        loadApp(): runs the real src/ scripts in a DOM-less VM, in index.html order
  unit/*.test.js         node:test. Engine, geography, state, data schemas, tools
  e2e/*.e2e.js           node:test + Playwright, loading index.html from file://
  e2e/screenshots/       written by e2e (gitignored)
  oracle/                Python reference: engine.py (Phase 2), geo.py (Phase 3), run.py, geo_runner.js
  fixtures/              small committed inputs: store tiles, receipts, geo/ (Phase 3), API recordings
```

## Commands (run from the repo root)

| Command | Runs |
|---|---|
| `npm test` | everything, in order: es5 → unit → oracle → e2e |
| `npm run test:es5` | the ES5 syntax gate over `src/` |
| `npm run test:unit` | `node --test "tests/unit/**/*.test.js"` |
| `npm run test:oracle` | `python3 -I tests/oracle/run.py` |
| `npm run test:e2e` | Playwright, one file at a time |
| `node --test tests/unit/x.test.js` | a single file |
| `node --test --test-name-pattern="§9.4" "tests/unit/**/*.test.js"` | by name |

## Loading the app in unit tests

```js
const { loadApp } = require('../helpers/load');
const { POD } = loadApp();                                 // all scripts
const { POD } = loadApp({ only: ['pod.js', 'engine.js'] }); // a subset, still in index.html order
const sb = loadApp({ globals: { localStorage: throwingStorage, Date: FixedDate } });
const sb2 = loadApp({ extra: ['tests/fixtures/stores/40_-74.js'] });
```

- Each `loadApp()` call gives a fresh, isolated sandbox. Don't share state between tests.
- **Inject time.** Anything date-dependent (the `syncCredits` dated-credit branch, credit reset timing) is tested with a fixed `Date` passed through `globals`.
- To test storage failures, pass a `localStorage` whose methods throw.

## Where expected values come from

This is the rule that matters most:

- **Allowed:** the spec, the orchestrator's hand-worked receipts in `tests/fixtures/receipts/` (each shows its arithmetic), and the Python oracle.
- **Never:** running the code under test and pasting what it printed. That tests nothing.
- Compare money with exact equality after `round2`, e.g. `assert.equal(r.net, 15.62)`. The engine already rounds each component (D-012), so there's no tolerance.

## Writing a test

- **Start the name with its spec reference:** `'§9.4 tip uses the pre-discount subtotal'`. Use `'D-006 …'` for a decision, or `'ISS-012 …'` for a regression test.
- **One behavior per test.** Make the arrange step readable: build the state with `POD.state.fresh()` and set only the fields that matter.
- **Every new behavior gets a test that would fail if the behavior broke.** Check this by reasoning through the mutation: "if step 5 used the pre-discount subtotal, this test's expected tax would be X, not Y."
- **Fixtures stay small.** Use a few store tiles: NYC `40_-74` and `40_-75` (a Brooklyn or Midtown 5-mile search needs both), and the Big Timber search cells `45_-111`, `45_-110`, `45_-109`, `46_-110` (`45_-110` holds only 2 stores). Never the full dataset.

## e2e

- Load `index.html` over `file://` (`pathToFileURL`). That's the strictest environment the page has to support.
- **Fail on any** `console` error or `pageerror`. Collect them from the first navigation onward. The one exception is the browser's own `ERR_FILE_NOT_FOUND` for a tile a test omits on purpose: allow only that, matched exactly, and only in that test (D-035, 2f657df).
- Build the site with `helpers.buildSite()` (fixture tiles in a temp dir). Expected prices come from `H.expected(saved state)` through the verified engine, state and insights modules, never from what the page shows (2f657df).
- Two viewports: phone 390×844 and desktop 1280×800. Assert there's no horizontal overflow.
- Use `data-testid` selectors, and wait with `waitForSelector` or `locator.waitFor`. **Never a fixed sleep.**
- Screenshots go to `tests/e2e/screenshots/<test>-<viewport>.png`, which the orchestrator reviews.

## Oracle (Phase 2 on; geography from Phase 3)

- `tests/oracle/engine.py` is an independent Python version of §4.2, written by the orchestrator. **Don't edit it to match the JS.** If they disagree, report it: one of them is wrong, and the orchestrator decides which.
- `run.py` generates N seeded random scenarios, runs both engines and diffs every receipt line. On a failure it prints the seed and the first mismatching line.
- `tests/fixtures/geo/synthetic.json` holds hand-worked geo cases (closed-form arithmetic in each case's `work`). `real.json` is generated by `geo.py --write` and is stale if `run.py` says so. Read `tests/fixtures/geo/README.md` before changing either.

## Never

- `test.skip`, `.todo`, commenting out, loosening an assertion or deleting a test to get green.
- Editing `src/` from a test task.
- Network access in unit tests.

## Reporting a failure

```
FAIL tests/unit/engine.test.js:88  '§9.4 tip uses the pre-discount subtotal'
  expected 4.20, actual 3.78
  diagnosis: tip is being computed after the promo is applied (engine.js:142)
```

## Learned rules

<!-- The reflector adds rules here. Each one cites its evidence. -->
- **Pin every lookup table to the source's own list, item by item.** A test that checks shape and range passes a state filed under the wrong PADD. Assert the expected group for each row from the source (c539fc3: DE, DC, MD on 1C, 12/12 green).
- **Pin aggregates by value, with independent expected numbers.** Cover an even count, a .5 rounding case and a min-vs-median case. A shape test passes a median that returns the minimum (1.7 review, findings 1 and 2).
- **Quote the issuer sentence beside every pinned credit amount.** A reimbursed membership is not an included one. The Platinum test pinned an over-credit because the card row said so (83f24d7, blocker).
- **Read data through `tests/helpers/data.js` `loadData()`, and compare VM-realm values with literals or JSON.** A `deepStrictEqual` against `[]` fails on VM-realm arrays even when empty. To copy one, use `Array.from(v, f)`, a `for` loop into `[]`, or JSON. Never `map`, `filter` or `slice`: they build their result with the VM array's own constructor, so 37 of 87 runner scenarios failed on prototypes (ISS-008: 8962e13, c4e21c4, a5b725d).
- **Run destructive negative tests on a throwaway copy in the scratch directory, never the real repo, even when a card's DONE WHEN says to.** The task 1.8 fix card ran `rm -rf` guard tests against the real repo. The guard held by luck (69b429b). If the card says otherwise, report NEEDS-CARD.
- **A scratch copy never links to the repo's `node_modules`.** Give it its own `npm ci` or none, and use a fresh directory (never reuse one you didn't create). At the Phase 5 close, `npm ci` in a stale scratch copy whose `node_modules` was a symlink to the repo's emptied the real `node_modules`, and the next unit run failed on a missing `acorn` (progress.md Phase 5 evidence).
- **Every generator rule that rejects input gets a failing-input test,** a fixture that must exit non-zero with the rule's message (platform evidence with no https URL: 56cc487, 1.7 review 3a; ISS-011 is still open for the cars generator). Phase 6's per-item rules had 6 of 11 branches tested, and dropping `0 <= v` passed every test (0f907b5). **A rule enforced only by a test gets a mutation check:** break the data in a scratch copy and show the test fails (observation ZIP vs state, 1.7 review 3b).
- **For each input and optional field, test missing, malformed and wrong-typed values, and assert the documented output (null, 0, the type), not just "differs from the right answer."** The fuzzer never generated a `directSvc` without `modes` or a deal without `scope` (793577b, c4e21c4). A `['s00']` brand passed `brand !== 's00'` because an array coerces to the key `s00`, which made the test a blocker (c8e1e5c). Out-of-range records and coordinates (95, 181, -90.001) had no test until c8e1e5c asserted `null` from every function. A setter that takes a value also gets an object and a cyclic object: `setPath` copied any value and overflowed on a cycle (9a17357).
- **A test that depends on a cache or on earlier tests builds its own collision and runs in its own sandbox, and must pass under `--test-name-pattern`.** The cross-table cache test never queried one point on two tables, so a global cache passed it by file order. The timing test's "uncached" points were partly cached by an earlier test (97ce6fe, c8e1e5c).
- **A differential runner must fail, never skip or serialize quietly.** Tag NaN and ±Infinity (they serialized to `null` and matched expected nulls). Check for −0 before JSON, since the round trip erases it (f10e69f). Fail when the JS file exists, and don't match on one exact string in `index.html` (a skip exited 0). Poison `POD.data`, `POD.S` and `Date` during calls, and call twice with the first result scribbled over. A Python regex that mirrors a JS one uses `[0-9]` with `fullmatch`: `\d` and `$` accepted records JS rejects (197acd1, contract review).
- **Pin every threshold and boundary at its exact value, in a receipt or fixture, and check each insight's condition for that state.** A `memberMin` flip from `>=` to `>` was caught by 15 of 500 fuzz scenarios and by no receipt (be9e129). The insights review found a `>=` vs `>` at break-even, a dropped `+ 0` and two iteration caps that survived 34 fixtures and 500 scenarios (f10e69f).
- **Before an e2e expectation names a store, a row or a missing field, run that exact state through the data path in Node.** Domino's is #33 of 82 for 10118, behind "Show all", and an unprofiled brand's `manualSubtotal` of 0 is valid, not missing. Builders' BLOCKED reports caught both orchestrator test bugs (2f657df).
- **A control a re-render can replace gets a type-then-click test in the same test:** fill the box, click the control, and assert the click counted and the clicked element is still attached and focused (identity, not only the outcome). A select detached by a settings commit passed an outcome-only check (5f60686, 2f657df; 3502730, b45868b).
- **When a data shape changes, grep every test for the old accessors (`[0]`, `[1]`, `[2]` on menu items).** A test that still passes on the old shape is broken. `r.menu[0][1] = 999` wrote a stray key and compared `undefined === undefined` until it was rewritten with write-landed checks; both reviewers flagged it (0f907b5, progress.md Phase 6).
- **Each test file must catch its own mutants: run it alone, with the other test files absent.** The Phase 4 state file missed a save without `cart`/`dealOn`, a `syncCredits` that ignored opt-ins, `setPath` accepting objects, and a regex matching only 2-segment paths. Other files covered them until the test-review fix round (a7861b6).
